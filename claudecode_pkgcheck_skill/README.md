# pkgcheck: Claude Code Security Skill

> AIコーディングエージェントのための「Point-of-Use（利用の瞬間）」セキュリティチェッカー

**pkgcheck** は、Claude Code などの AI エージェントが提案する Python (`pip`) / Node.js (`npm`) パッケージをインストールする**前**に、その安全性を証拠に基づいて監査するためのカスタムスキルです。

タイポスクワッティング（Typosquatting）、AIのハルシネーションによる偽パッケージ提案、サプライチェーン攻撃のリスクを、レジストリ・GitHub・OSV（Open Source Vulnerabilities）のデータに基づいて可視化します。

> 📖 **詳細な解説・開発の背景**: 
> 本ツールが解決するAI時代特有のセキュリティリスクや、AIエージェントに厳格な判定をさせるための「プロンプト設計の裏側」については、以下の記事で詳しく解説しています。
> 👉 [AIが提案した pip install / npm install を信用していいのか？fail-closedで検証する「pkgcheck」](https://zenn.dev/dxclab/articles/ac83e229177c2c)

## なぜこのツールが必要なのか？

AIコーディングエージェントの普及により、開発者はAIが提案した `pip install` や `npm install` コマンドを、十分に検証せずに実行してしまうリスクが高まっています。

既存の `npm audit` や `pip-audit` はインストール**後**の既知の脆弱性をチェックする「事後監査ツール」ですが、悪意あるパッケージはインストール時のスクリプト（`preinstall` など）でシステムを侵害する可能性があります。

`pkgcheck` は、**「インストールする直前」**に特化し、以下のAI時代特有の脅威に対抗します：

1. **タイポスクワッティングの自動補正**: AIがTypoを「気を利かせて」正規パッケージとして扱ってしまうのを防ぐ
2. **Shai-Hulud型攻撃（ハルシネーションの悪用）**: AIが存在しないパッケージ名を提案し、それを先回りして登録した悪意あるパッケージをインストールさせられるのを防ぐ
3. **正規パッケージへのサプライチェーン攻撃**: 「有名だから安全」というAIの推論を排除し、事実ベースの証拠のみで判断する

| | pip-audit / npm audit | /pkgcheck |
|---|---|---|
| 対象 | 既知のCVE・脆弱性 | パッケージの正当性・Typo |
| タイミング | インストール後でも可 | インストール前が主な用途 |
| 得意なこと | 「このバージョンは安全か」 | 「そもそも本物のパッケージか」 |

## 3つの設計原則

このスキルは、AIの「推論」や「気遣い」によるセキュリティリスクを排除するため、厳格なルールに基づいて設計されています。

1. **Evidence-based（証拠ベース）**: AIに推論させず、PyPI/npmレジストリ、GitHub API、OSV APIから取得した事実（バージョン、スター数、最終更新日、CVE等）のみを判断材料とします。
2. **Exact Name Match（完全一致の強制）**: 入力されたパッケージ名と公式名が1文字（ハイフン、アンダースコアの違い等）でも異なれば、即座に `HIGH RISK` と判定します。ファジーマッチは一切許容しません。
3. **Fail-Closed（安全側に倒す）**: 証拠が1つでも取得できない場合は `UNKNOWN` とし、インストールを推奨しません。「危険という証拠がない」ことを「安全」とはみなしません。

## 動作要件 (Prerequisites)

このスキルは内部で以下のOSコマンドを利用してデータ収集を行います：
- `curl`（APIからのデータ取得）
- `python`（JSONデータのパース）
- `rm`（一時ファイルのクリーンアップ）

**動作確認環境**:
- Windows + **Git Bash**


> **環境依存への対策**: 
> AIが巨大なJSONをシェル経由で直接処理する際のクォーティングやエンコーディング問題（特にWindows環境）を回避するため、スキル内部で動的にPythonスクリプトをファイルとして生成し、ローカルのPythonで安全にパースする堅牢な設計になっています。万が一コマンドの実行環境に差異があっても、Claude Code自身がエラーを検知して自動的に代替手段（Tavily Extractなど）でリトライを試みます。

## セットアップ手順

Claude Code のカスタムスキルとして動作します。

1. 本リポジトリの `skill.md` をダウンロードします。
2. 以下のディレクトリに配置します：
   - `.claude/skills/pkgcheck/skill.md`

ファイルを配置するだけで、チャット上で `/pkgcheck` コマンドが利用可能になります。

## 使い方とユースケース

### ユースケース1: AIがinstallを提案してきたとき
AIが提案してきたコマンドを実行する前に、そのままパッケージ名を渡して検証します。
```bash
/pkgcheck fastapi uvicorn sqlalchemyy
```
*(上記の場合 `sqlalchemyy` がタイポスクワッティングとして検出されます)*

### ユースケース2: 新しいライブラリを導入する前に
採用を検討しているパッケージのメンテナンス状況やセキュリティ情報を確認します。
```bash
/pkgcheck requests beautifulsoup4
```

### ユースケース3: プロジェクトの棚卸し
`requirements.txt` または `package.json` に含まれるパッケージを一括で検証します。
```bash
/pkgcheck @requirements.txt
```
> **注意**: 一括チェックはパッケージ数に比例して時間がかかります（各パッケージごとに複数のAPIを呼び出します）。大規模なプロジェクトでは段階的にチェックすることを推奨します。

エコシステム（npm/PyPI）は自動判定されますが、明示することも可能です。
```bash
/pkgcheck --npm express
/pkgcheck --pip requests
```

## 出力例

複数のパッケージを検査した場合、各パッケージの詳細レポートに加え、最後に以下のようなサマリーが出力されます。

```text
==================================================
FINAL SUMMARY
==================================================

【リスク分類】
LOW RISK:
- fastapi

CAUTION:
- express（v5.2.1 / 既知CVE 5件 / 最新版で多くは修正済み）

HIGH RISK:
- axios（MAL-2026-2307: マルウェアコードがOSVに登録。影響バージョン要確認）
- crossenv（確定マルウェア / CVE-2017-16074 / 環境変数窃取）
- sqlalchemyy（タイポスクワッティング疑い: sqlalchemy との不一致）

UNKNOWN:
- なし

【推奨アクション】
ALLOW（条件付きインストール可）:
- fastapi
- express — v5.2.1 を使用し、各CVEの適用可否をレビューすること

BLOCK（インストール禁止）:
- axios — MAL-2026-2307 の影響バージョンを確認するまでインストール禁止
- crossenv — マルウェア確定。代替: cross-env
- sqlalchemyy — タイポスクワッティング疑い。代替: sqlalchemy
==================================================
```

## 取得する情報

`/pkgcheck` は以下の情報を収集します：

1. **公式レジストリ (PyPI / npm)**: 公式名、最新バージョン、パブリッシャー、初回/最終リリース日、リポジトリURL
2. **GitHub リポジトリ**: スター数、最終push日、アーカイブ状態、オーナー情報
3. **OSV (Open Source Vulnerabilities)**: 既知の脆弱性（CVE）、マルウェアエントリ

## 制約・制限事項（Disclaimer）

**このツールは安全性を保証するものではなく、人間が判断するための証拠を揃えるツールです。**

- **最終判断は人間が行う**: `LOW RISK` と判定されても、OSVに未登録のゼロデイ脆弱性や最新のサプライチェーン攻撃が存在する可能性があります。`UNKNOWN ≠ SAFE` であると同時に、`LOW RISK ≠ 絶対安全` です。
- **OSVの限界**: 新規に登録された悪意あるパッケージは、OSVのデータベースに反映されるまでにタイムラグがあります。
- **AIの確率論的な振る舞い**: プロンプトで厳格なルールを定義していますが、大規模言語モデルの性質上、ネットワーク状況やコンテキスト長によって100%ルール通りに動作しないケースも想定されます。
- **実行環境の制約**: 大量のパッケージを一括検査する場合、APIのレートリミットや処理時間に制約を受けます。

インストール後には、必ず `pip-audit` や `npm audit` などの専用ツールで定期的なスキャンを行ってください。
